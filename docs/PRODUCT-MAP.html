One engine, three hosts. The money path in core/ (tip → price → queue → job, plus token minting rules) runs unchanged inside the cloud service, the desktop app's local bridge, and the developer demo rig. That is why the app can work offline in "local mode" for demos, and why the hosted product never needed a second implementation.
What never leaves the streamer's PC. Webcam frames go from OBS to the router and to Decart directly over WebRTC. The cloud only ever sees prompts, images, payments and job status. The cloud front door actively rejects the local signaling plane.

Streamer onboarding

From the website to live in one sitting. The wizard appears on the first launch only and can be rerun from the tray menu.

  1. Download from the site

    Click "Get the app". macOS gets a universal DMG, Windows a one-click per-user installer. No account yet.

    site → GitHub Releases latest
  2. Open it: the wizard appears

    The window opens on /setup instead of the main app until setup is marked done. Nothing else is touched on first run.

    app · app-state.json setupDone
  3. Sign in with Twitch

    The only step-1 path in shipped builds. The control-plane URL is baked in at build time, so there is no server field and no API key to paste.

    app ↔ cloud · Twitch OAuth
  4. Pick the camera

    Choose the OBS Virtual Camera as the input. OBS's virtual camera must output "Source" so the AI layer doesn't feed back into itself.

    app · getUserMedia
  5. Connect OBS

    If obs-websocket is off, one button enables it in OBS's config and starts OBS. The app then adds the "AI Hijack" Browser Source to the scene for you.

    app · obsDiscovery + ensureBrowserSource
  6. Done: go live

    The app sits in the tray with a panic hotkey. The dashboard on the cloud holds presets, pricing and history. Share the portal link with viewers.

    tray · reality-hijack.fly.dev/dashboard
Viewer onboarding is nothing. A viewer opens the streamer's portal link in any browser, picks an effect, pays with a card, and gets a claim code. No account, no install.

One hijack, start to finish

The sequence behind the diagram's arrows. Every exit, including panic and a frozen PC, ends in the same teardown that hides the OBS layer before dropping the Decart session.

  1. Viewer submits

    Prompt or preset plus an optional reference image goes to the cloud. Presets are resolved server-side from an id so text can't be spoofed.

    portal → cloud
  2. Safety chain runs

    All checks run before any claim code exists, and the portal streams each result live. A borderline result is rejected, not parked, unless the streamer opted into approvals.

    cloud · content safety
  3. Viewer pays

    Stripe Checkout charges the card to the streamer's connected account. The webhook marks the submission paid; $1 = 1 second.

    Stripe → cloud
  4. Engine queues the job

    The tip is paired with the submission, priced, and queued FIFO behind any running hijack with a cooldown gap.

    cloud · core engine
  5. App receives the job

    The cloud mints a Decart token that expires at the tip's length and dispatches the job to the streamer's router over WebSocket.

    cloud → app
  6. Router goes live

    Webcam frames stream to Decart, restyled frames come back and are looped into the OBS Browser Source. The layer is shown only once Decart reports generating and frames are actually flowing.

    app ↔ Decart ↔ OBS
  7. Countdown ends

    Three independent caps bound the cost: the router's timer, a local watchdog, and the token's own max duration on Decart's side.

    app · state machine
  8. Teardown and revert

    Hide the OBS layer, then drop the Decart session, delete the upload, write the ledger. The stream shows the plain webcam again.

    app → cloud ledger

Names you'll see in the code

router
The streamer-side page that captures the webcam and runs a hijack. In the app it lives in bundled Chromium; in the demo rig it is a Chrome tab at /router.
viewer page
Not the viewer's portal. /viewer is the display-only page inside the OBS Browser Source that shows the AI feed.
portal
The viewer-facing page where prompts are submitted and paid for: /portal locally, /c/<channel> hosted.
local bridge
The app's built-in sidecar on 127.0.0.1:17712: OBS control, page serving, and WebRTC signaling. In cloud mode it holds no money logic.
cloud mode / local mode
Cloud mode is the product: signed in, the key lives on the server. Local mode (pasted keys, RH_LOCAL_MODE=1) is the offline demo for developers.
demo rig
npm run dev: the sidecar on :7712 plus the web app on :5173, no cloud, for testing the whole loop on one machine.
